- (direction) Работа выделена из CAP-7–CAP-10 в отдельный малый контракт без эпиков, stories.yaml и sprint-status.
- (capability) CAP-10 сохраняется: tests, lint, type check, HACS Action, Hassfest и version parity доказывают release readiness.
- (constraint) CI запускается на pull request, push и release candidate без errors или ignored failures.
- (constraint) Version parity сравнивает manifest.json, pyproject.toml, CHANGELOG heading и ожидаемый tag v0.0.1; schema_version: 1 не связан с package version.
- (constraint) HACS Action использует category integration; Hassfest валидирует metadata, translations и config flow.
- (constraint) Live tenant acceptance probe и HACS install smoke остаются явными внешними release gates, если им нужны credentials или опубликованный release.
- (constraint) Runtime CAP-1–CAP-6 и AD-1–AD-13 не изменяются; push и GitHub Release запрещены без отдельного подтверждения.
- (event) Coherence validation PASS: capability имеет intent/success, границы и success signal тестируемы.
- (event) Preservation validation PASS: все load-bearing требования CAP-10 и validation gates сохранены.
