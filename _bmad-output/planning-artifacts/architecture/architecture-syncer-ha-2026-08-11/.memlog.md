- (direction) Пользователь выбрал Fast path и только ARCHITECTURE-SPINE.md как build-substrate для реализации.
- (constraint) Наследован SPEC: сервер Time является интеграционной поверхностью; WebSocket основной транспорт; REST только проверка и recovery; OAuth, PAT и session token обязательны; скрытый fallback запрещён.
- (constraint) Наследован SPEC: собственные, повторные и не-direct сообщения не публикуются; интеграция выдаёт доменное событие, а действия ламп, TTS и push остаются в автоматизациях Home Assistant.
- (version) Home Assistant Core 2026.8.x принят как baseline; официальные developer docs на 2026-08-11 подтверждают ConfigEntry runtime_data, UI config flow, reauth и асинхронный lifecycle.
- (version) Time API v4 принят как внешний контракт; официальные docs подтверждают /api/v4/users/me, /api/v4/users/login, /api/v4/websocket, channel types D/G/P/O и OAuth endpoints /oauth/authorize и /oauth/access_token.
- (decision) AD-1: применяется hexagonal event-driven pipeline. Binds all. Prevents transport, auth and Home Assistant lifecycle logic from leaking into message classification. Rule: Time adapters feed canonical domain messages through pure filters and dedupe into one HA event publisher; dependencies point inward.
- (decision) AD-2: одна ConfigEntry владеет ровно одной парой normalized tenant origin plus Time user_id; несколько entries разрешены. Binds CAP-1 and all state. Prevents account data, reconnect tasks and dedupe namespaces from mixing. Rule: unique_id is tenant origin plus user_id and runtime_data owns all per-entry objects.
- (decision) AD-3: OAuth, PAT and session login implement one TokenProvider boundary but remain explicit tagged modes. Binds CAP-1. Prevents hidden auth fallback and branching in REST or WebSocket clients. Rule: OAuth uses HA application_credentials and authorization-code refresh flow; PAT stores supplied bearer; session POSTs login_id/password/optional MFA to users/login, stores only returned Token and immediately discards password and MFA.
- (decision) AD-4: setup is gated by a shared identity and capability check. Binds CAP-1 and CAP-2. Prevents an accepted token for the wrong account or tenant from starting the listener. Rule: normalize HTTPS origin, call users/me, establish authenticated WebSocket through hello, record immutable user_id and server_version, and require target-tenant acceptance probe evidence before claiming DM support.
- (decision) AD-5: each ConfigEntry owns exactly one supervised WebSocket task. Binds CAP-2 and CAP-6. Prevents duplicate listeners and divergent retry behavior. Rule: task starts after setup gate, stops and closes on unload, reconnects transient failures using capped exponential full-jitter backoff, resets after healthy hello, and sends auth failures to reauth rather than retrying forever.
- (decision) AD-6: only canonical new posts in channel type D pass. Binds CAP-2 and CAP-3. Prevents group/private channels, edits, system posts and own posts from reaching automations. Rule: accept event posted, parse post defensively, verify channel type D from event or REST-backed cache, require post.user_id different from identity user_id, and fail closed when identity or channel type is unknown.
- (assumption) Первая версия трактует личное сообщение только как 1:1 direct channel type D; group direct type G и private type P исключены до явного расширения контракта.
- (decision) AD-7: dedupe state is durable per ConfigEntry and marked before publication. Binds CAP-4 and CAP-6. Prevents duplicate HA events across reconnects and restarts. Rule: serialize check-and-mark with one async lock, key by post_id inside entry namespace, persist via HA Store before async_fire, retain 5000 newest IDs or 24 hours whichever is smaller, and never evict the newest watermark early.
- (decision) AD-8: the only public automation contract is event type time_messenger_event with schema_version 1 and type direct_message. Binds CAP-5. Prevents independently built automations from choosing incompatible names and payloads. Rule: required flat keys are schema_version, type, config_entry_id, account_user_id, post_id, channel_id, sender_user_id, message_text, created_at; optional additive keys include sender_username, root_id and file_ids; raw Time payload and secrets are never emitted.
- (assumption) Полный текст сообщения включён по умолчанию для TTS; option include_message_text может заменить message_text на null and set text_redacted true without changing schema version.
- (decision) AD-9: failure classes have one owner and one HA outcome. Binds CAP-1 and CAP-6. Prevents retry storms and misleading reauth. Rule: 401 or terminal OAuth refresh starts reauth; DNS, timeout and 5xx keep supervised reconnect; 429 honors Retry-After or rate-limit reset; malformed events are dropped with redacted debug metrics; unsupported tenant capability raises a Repair issue.
- (decision) AD-10: all Time protocol details stay behind a v4 adapter and canonical models. Binds CAP-1 through CAP-6. Prevents v5 drift and raw wire shapes from infecting HA code. Rule: no production module outside api imports Time response shapes; v5 or tenant deviations require a new adapter selected only after explicit capability detection.
- (decision) AD-11: no companion daemon, broker or inbound HA webhook is deployed. Binds operational envelope. Prevents two process owners and new ingress exposure. Rule: the custom component runs inside one HA Core instance, uses the HA-managed aiohttp session for outbound HTTPS/WSS, verifies TLS, supports private CA only through the host trust store, and does not offer verify_ssl false.
- (decision) AD-12: target-tenant acceptance is contract-tested before a release is labelled compatible. Binds CAP-2 and CAP-3. Prevents documentation-only assumptions about private WebSocket coverage. Rule: probe fixtures must demonstrate hello plus one posted event for D, rejection of G/P/O and self posts, reconnect duplicate replay, and all three auth modes that the tenant enables; unavailable administrative modes remain implemented but reported unsupported.
- (direction) REST backfill after offline gaps is deferred in v1 because public Time docs describe per-channel since reads but no global replay contract; revisit when the target tenant supplies a tested cursor strategy. Reconnect and durable dedupe remain mandatory.
- (direction) Event entities, device registry objects and sensor entities are deferred because the requested public contract is a generic bus event and storing message text in entity state would widen retention.
- (direction) Distribution through HACS versus manual installation, CI provider and release automation are deferred to build/release planning; source structure and runtime contract do not depend on that choice.
- (question) OAuth scopes, PKCE acceptance, client registration and exact redirect URI remain tenant inputs; architecture fixes authorization-code plus refresh and rejects implicit grant.
- (question) Session SSO-only tenants may reject users/login; session mode is then reported unsupported unless the tenant provides a documented session-token acquisition endpoint.
- (event) Fast-path architecture decisions complete; unresolved tenant facts are bounded as explicit assumptions, questions or deferred items.
- (decision) AD-3 tightened after review: OAuth Application Credential auth_domain equals normalized tenant origin and custom async_get_auth_implementation derives same-origin authorize and token endpoints; OAuth tokens belong to ConfigEntry, PAT/session bearer to ConfigEntry.data, credentials to application_credentials.
- (decision) AD-4 tightened after security review: authenticated REST and WebSocket never follow redirects or send bearer cross-origin; HTTPS is mandatory except explicit loopback test fixtures; tenant origin is immutable after identity binding and changes use reconfigure plus full validation.
- (decision) AD-5 tightened after review: reconnect delays are full-jitter over exponential caps 1,2,4,8,16,32,60 seconds, reset only after 60 healthy seconds; unload cancels and awaits the task and a runtime generation guard rejects late callbacks.
- (decision) AD-6 tightened after current-tech review: v1 accepts only posted events whose canonical post.type is empty, excluding system and integration post types.
- (decision) AD-7 clarification: HA event bus has no transactional acknowledgement, so crash-safe exactly-once delivery is impossible; architecture prioritizes no duplicates with durable save-before-fire and exposes stable post_id. This is at-most-once across process crashes and exactly-once suppression for replays after successful persistence.
- (decision) AD-8 privacy choice supersedes earlier assumption: include_message_text defaults false; message_text is required but nullable and text_redacted true until user explicitly opts in. Raw text is never logged or included in diagnostics.
- (decision) AD-13 added after review: unload only stops runtime; config-entry removal also purges local bearer/OAuth token data and dedupe Store, calls users/logout for session when reachable, and performs OAuth/PAT remote revoke only through a documented supported endpoint.
- (version) Compatibility claim narrowed after review to verified baseline Home Assistant Core 2026.8.1; no unverified upper bound is asserted.
